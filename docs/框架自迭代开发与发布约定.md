# AI-SDLC 框架自迭代开发与发布约定

## 开发入口

AI-SDLC 自身开发必须先读取项目根目录 `AGENTS.md`，并遵循：

- `src/ai_sdlc/rules/pipeline.md`
- `src/ai_sdlc/rules/git-branch-rule.md`
- `docs/product-contract.md`

默认代理为 Codex，项目 Shell 为 PowerShell。命令应优先使用项目虚拟环境：

```powershell
uv sync
uv run ai-sdlc adapter status
```

## 变更流程

1. 从当前项目事实确认需求和影响面；
2. 为新行为或缺陷编写失败测试；
3. 实现最小、可验证的变更；
4. 运行定向测试和静态检查；
5. 执行 `ai-sdlc run --dry-run` 与约束验证；
6. 运行本地对抗 PR 审查；
7. 完成全量测试、构建和制品 smoke；
8. 更新用户可见文档和交付证据。

- Git 仓库固定为 `https://github.com/SinclairPan/Ai_AutoSDLC`；
- 产物版本固定从 `pyproject.toml` 读取；

## v1.0.5 prepared-disabled 候选记录

`WorkItem 010 three-PR release migration` 使用三次独立审查与合并来隔离准备、启用和结果真相：

1. PR1 修复 workflow 可装载性，增加 read-only load-probe、`expected_candidate_sha` 和唯一 actual-generation dispatch 检查，并迁移 1.0.5 候选面；三个发布开关保持字符串 `false`。
2. PR2 只能把三个开关从 `false` 改为 `true`，不得混入版本、逻辑、测试或文档变化；合并后从精确 protected-main writer 只执行一次实际 generation。
3. PR3 无论成功或失败都把三个开关恢复为 `false`，并按远端不可变事实收口公开真相。

PR1 状态固定为 `v1.0.5 release candidate / not published / prepared-disabled`；`last published version is v1.0.2`。不得上传、发布或下载 v1.0.5 候选。load-probe 必须只读且与 actual release 的 run identity 分离；实际 generation 一旦被 dispatch 或创建任一 namespace，任何失败都执行 terminal generation burn，不 rerun、不 redispatch、不清理、不复用证据。

实际 dispatch 创建后、软件 tag ref 创建前，`Actions history duplicate-run detector` 只在 `retention and no-delete trust boundary` 内阻止 fresh redispatch；它是运行期 fail-closed 探测器，`not an immutable authority`。删除或隐藏 matching run 属于受信 GitHub 控制面的越权篡改，不是恢复路径。探测器必须读取 repo-wide workflow-dispatch 历史及每个 matching run 的精确 head workflow，只把三个 enablement gate 均为规范字符串 `true` 的 run 计入实际 generation；prepared-disabled PR1 即使误选 `mode=release` 也不消耗 PR2，而启用后的第二次实际分发必须拒绝。软件 tag ref 一经成功创建，`protected tag namespace becomes the durable burn authority`，由 active no-bypass ruleset 与 namespace absence 检查永久拒绝移动、重建或复用。
