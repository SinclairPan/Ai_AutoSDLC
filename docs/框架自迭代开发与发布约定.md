# AI-SDLC 框架自迭代开发与发布约定

本约定只定义 AI-SDLC 仓库自身的普通开发与发布流程，不为普通用户项目增加治理负担。

## 开发边界

- 仓库源码是本地开发的控制实现，使用 `uv run ai-sdlc ...` 执行治理和验证。
- 每项变更使用独立分支或 worktree，保持变更范围可审查。
- 代码合入前运行相关测试、完整约束检查、lint 和构建验证。
- 不把本地凭据、运行缓存、临时证据或用户项目状态提交到仓库。

## 保留的复核能力

AI-SDLC 只保留以下三项产品能力：

1. Local PR Review 在提交前调用独立本地代理检查当前 Git 变更。
2. 代码精简分析只给出建议，可因正确性和交付价值灵活突破，不阻断 Loop 或发布。
3. Requirement、Design Contract、Implementation、Frontend Evidence、Local PR Review 五类结果由当前代理按内容临时选择最多两名只读专家复核；专家只审查与 `input_digest` 同次读取返回的 `review_snapshot`，不得重新打开可变工件路径；同一结果最多一次修复后复审。

专家身份和结论只存在于当前对话。系统不创建 review session、ledger、certificate、attestation、authority/store、Shadow/Enforce 激活状态或第二套 close 流程。

## Pull Request

- PR 必须说明目的、范围、测试结果和剩余风险。
- Local PR Review 的验证证据必须在动态专家复核之前记录，最终报告只在复核无可操作问题后生成。
- 专家不可用、超时或返回无效结果时，Loop 保持 `needs_review`；不得把失败解释为通过。
- 有发现时由原实现代理修复，并只允许一次复审；仍有问题则停止并报告，不进入无限对抗循环。
- 通过后由当前代理调用既有 close，再走普通 CI、分支保护和合并流程。

## 普通发布流程

发布使用 `.github/workflows/release-build.yml` 和 `.github/workflows/release-artifact-smoke.yml`：

1. 从已通过保护检查的 main 提交创建版本 tag。
2. 构建 wheel、sdist 和三个目标平台的离线包。
3. 在 Windows、macOS、Linux 执行安装与 smoke。
4. 验证版本、manifest、checksum 和公开文档一致。
5. 由明确授权的维护者上传并发布 GitHub Release。

发布流程不生成 Release Proof、Permanent Certificate、generation burn、release attestation 或额外 authority 指针。GitHub Release、tag、普通 CI 和分支保护是发布所需的现有平台能力。

## 当前版本事实

- 仓库源码版本：`1.0.5`。
- 当前公开稳定版本：`1.0.2`。
- `1.0.5` 的文件名和安装命令在合并前仅用于本地候选验证；只有普通发布流程成功完成后，公开文档才能切换到该版本。
- 历史未发布候选不构成当前发布授权，也不要求保留专用恢复或烧毁机制。

## 发布一致性面

发布变更必须同步检查 `README.md`、`USER_GUIDE.zh-CN.md`、`packaging/offline/README.md` 和 `docs/pull-request-checklist.zh.md`。项目地址固定为 `https://github.com/SinclairPan/Ai_AutoSDLC`。

当前源码候选的离线制品名为：

- `ai-sdlc-offline-1.0.5-windows-amd64.zip`
- `ai-sdlc-offline-1.0.5-macos-arm64.tar.gz`
- `ai-sdlc-offline-1.0.5-linux-amd64.tar.gz`

构建必须生成 `SHA256SUMS` 和每个归档对应的 `.sha256` 文件。
