# AI-SDLC 离线产品站视觉与交互设计规范 V2

状态：对抗评审通过（2026-08-17）。

本规范定义 AI-SDLC v3.0.1 离线产品站的页面结构、视觉系统、交互方式和小屏适配。它不包含 HTML、CSS 或 JavaScript 实现。

## 1. 产品站任务

产品站需要让第一次接触 AI-SDLC 的中国评委或开发团队快速理解三件事：

1. Loop Engineering 如何把一次生成推进为可验证、可恢复、可关闭的交付。
2. Dynamic Expert Review 如何按风险引入独立专家，又避免多 Agent 无边界扩张。
3. Platform Capabilities 如何把跨 AI 工具接入、续作、前端治理与验证证据留在项目中。

页面应像成熟开发者产品官网，不像比赛材料、汇报 PPT、功能清单或伪造的管理后台。

## 2. 站点结构

站点使用五个独立页面和一份独立用户指南。主页面之间使用相对链接，双击 `index.html` 后即可浏览。

| 页面 | 文件建议 | 主要任务 |
|---|---|---|
| AI-SDLC | `index.html` | 建立产品定位，承载产品实录，分发三条价值主线 |
| Loop Engineering | `loop-engineering.html` | 解释 Loop 如何持续收敛并获得 Close 条件 |
| Dynamic Expert Review | `dynamic-expert-review.html` | 解释 Bounded Dynamic Expert Review Graph 的职责、边界与价值 |
| Platform Capabilities | `platform-capabilities.html` | 展示支撑两条主线的项目级工程能力 |
| Downloads & Docs | `downloads-docs.html` | 提供 GitHub、Release、README、用户指南和离线安装包链接 |
| 中文新用户指南 | `docs/USER_GUIDE.zh-CN.html` | 在文档内部提供空项目 / 已有项目 × 在线 / 离线 × 三平台的 12 条自包含路线，不进入主导航 |

主导航固定使用英文：`AI-SDLC`、`Loop Engineering`、`Dynamic Expert Review`、`Platform Capabilities`、`Downloads & Docs`。产品价值、正文、交互提示和状态解释使用中文。

## 4. 全局视觉系统

### 4.1 色彩

| 用途 | 建议色值 | 说明 |
|---|---|---|
| 主文字 | `#111827` | 标题与高优先级正文 |
| 次文字 | `#52627A` | 解释性正文 |
| 品牌深蓝 | `#0B1F5E` | Logo、导航、深色强调 |
| 行动蓝 | `#1548D8` | 主按钮、链接、当前状态 |
| 浅蓝表面 | `#EEF4FF` | 选中态和轻量信息区 |
| 分隔线 | `#DCE3EE` | 只在结构需要时使用 |
| 暖光 | `#FFCF9F` | 只用于主视觉光源，不用于状态提示 |

页面以白色和浅灰蓝为主。颜色负责指示操作和状态，不用不同底色把每段内容包装成卡片。

### 4.2 字体与层级

离线站不加载网络字体。中文优先使用系统无衬线字体栈，英文与数字沿用相同字族，避免中英文气质分裂。

| 层级 | 桌面建议 | 小屏建议 | 用途 |
|---|---:|---:|---|
| Hero 标题 | 56–64px | 42–48px | 页面唯一主张 |
| 页面标题 | 44–52px | 36–42px | 详情页定位 |
| 分区标题 | 30–36px | 26–30px | 内容区主结论 |
| 条目标题 | 20–24px | 18–22px | 价值或状态标题 |
| 正文 | 16–18px | 15–16px | 说明文字 |
| 标签 | 12–13px | 12px | 英文 eyebrow、状态、来源 |

正文每行不超过约 34 个中文字符。一个区块只允许一个最强标题，避免页面上连续出现多个同等重量的大字。

### 4.3 容器与节奏

- 内容最大宽度建议 1240px；常规左右安全区不小于 40px。
- 1366px 宽笔记本上，左右安全区可收缩到 28–32px。
- 主导航高度建议 68–72px。
- 首屏 Hero 不超过约 590px 高；视频橱窗保持 16:9，不独占整行。
- 详情页主体优先使用一个工作区和局部 Tab，不连续堆叠五六个大章节。
- 圆角只用于按钮、视频和确有容器含义的表面。普通内容不使用圆角卡片。

## 5. 全局交互

### 5.1 主导航

- 当前页面使用蓝色下划线或文字强调，不增加胶囊底色。
- GitHub 保持右侧外链位置并显示外链图标。
- 页面宽度不足 1120px 时，保留 Logo、当前页面标题和菜单按钮；展开后显示完整五项导航与 GitHub。
- 键盘焦点必须清晰；导航顺序与视觉顺序一致。

### 5.2 页面内部导航

详情页使用局部 Tab 或分段控制器切换同一主题的不同观察角度。Tab 必须改变页面中的主要说明和图形，不能只是把长文章隐藏起来。

浏览器前进、后退或刷新后，应能够恢复当前 Tab。实现可使用 URL hash，不依赖后台路由。

### 5.3 动效

- 页面进入、Tab 切换和玻璃层轻微位移可使用 160–240ms 的克制过渡。
- 不使用自动轮播、持续漂浮、滚动劫持或必须等待的开场动画。
- `prefers-reduced-motion` 下关闭非必要动效。

## 6. 首页：AI-SDLC

### 6.1 首屏结构

左侧：

- 主标题：`把不确定的 AI 生成，变成可验证的工程交付`。
- 一句解释：AI-SDLC 把需求、Loop、证据与独立复核带进项目，让 AI 知道下一步，也知道什么时候必须停下。
- 主操作：`观看产品实录`。
- 次操作：`从 Loop Engineering 开始`。
- 辅助事实：版本、本地优先、开源、已支持的 AI 工具入口。

右侧：

- 16:9 产品实录橱窗，宽度约占 Hero 的 44%–48%。
- 未提供视频时显示同尺寸 Poster 和“产品实录即将加入”，不能出现假时长或假播放进度。
- 点击 Poster 或播放按钮后使用原生 `<video controls>`。
- 必须支持原生全屏、字幕轨道入口和键盘播放控制。

### 6.2 三条价值导航

总句：`真正的差距，不在生成速度，而在交付能力。`

| 页面 | 价值标题 | 简述 | 入口 |
|---|---|---|---|
| Loop Engineering | 从一次生成，到持续完成 | Loop 把目标、执行、验证、反馈与修复连成闭环；证据满足 Close 条件，任务才真正完成 | 看 Loop 如何把任务做完 |
| Dynamic Expert Review | 从模型自审，到专家对抗 | 系统按风险选择独立只读专家；Findings 回到原 Writer 修复，专家数量和复审轮次都有边界 | 看专家如何挑战关键结果 |
| Platform Capabilities | 从零散 Skills，到项目级工程系统 | 跨 AI 工具接入、断点续作、前端方案、组件规范与浏览器验收证据都留在项目中；换工具，项目规则、状态与工件不必重建 | 查看完整平台能力 |

三条内容使用编辑式三栏，不使用三张独立卡片。每个入口紧跟对应解释，整行均可点击，但必须保留清晰文本链接。

## 7. Loop Engineering 页面

### 7.1 页面主张

标题：`让 AI 开发任务，从明确需求走到可验证完成`。

解释：Loop Engineering 不是固定流程图，而是一组有输入、有状态、有证据和退出条件的反馈闭环。缺口回流，失败可恢复，满足条件后才允许 Close 或 Freeze。

主操作：`查看一个 Loop 如何收敛`。

### 7.2 核心工作区

页面中心使用“Loop 工作台”解释真实机制，不制作虚构后台界面。

上方阶段选择：

- Requirement
- Design Contract
- Implementation
- Frontend Evidence

Local PR Review 以跨阶段终审轨道出现，不与四类 Loop 画成完全相同的第五节点。

选中一个阶段后，工作区展示四列：

1. 当前输入：目标、工件或候选身份。
2. 当前状态：`needs_user`、`needs_fix`、`needs_review` 或可关闭状态。
3. 反馈动作：补充输入、回到原 Writer、运行验证或恢复复核。
4. 完成条件：当前阶段允许 Close 或 Freeze 的条件。

### 7.3 证据带

工作区下方保留一条窄证据带，按当前 Tab 展示可以检查的工件类型，例如 input digest、test/lint/build 结果、Browser Gate 或 Review Pack。它用于证明状态来自项目事实，不显示虚构成功率和节省时间数字。

### 7.4 页面收束

收束句：`Loop 的价值不是不停重试，而是在每次反馈后知道该继续、该修复，还是该停下。`

操作：`继续了解专家如何挑战 Loop 结果`，进入 Dynamic Expert Review。

## 8. Dynamic Expert Review 页面

### 8.1 页面主张

标题：`让关键结果先经独立挑战，再进入下一步`。

解释：AI-SDLC 根据当前结果的主要风险选择一名 Primary Expert；只有存在明确第二风险面时，才加入一名 Cross-risk Expert。专家只读同一冻结输入，原 Writer 保留修改权。

主操作：`查看专家如何被选择`。

### 8.2 Bounded Dynamic Expert Review Graph

该图是页面核心视觉。它解释职责和信息流，不画成持久运行时、图数据库或第二套状态机。

默认图形关系：

```text
Writer → 冻结输入与 digest → Primary Expert
                           ↘ 条件满足时的 Cross-risk Expert
专家 Findings → 原 Writer 修复 → 最多一次复审 → Close 或 needs_review
```

图形上方提供五个风险视角 Tab：Requirement、Design Contract、Implementation、Frontend Evidence、Local PR Review。切换后只改变：主要风险、Primary Expert 角色、可能的交叉风险、典型 Finding。数量边界保持不变。

### 8.3 三条不可突破的边界

使用一条横向规则带，不做卡片：

- 专家只读，不直接修改候选。
- 默认一名 Primary Expert，明确交叉风险时最多再加一名专家。
- 最多一次复审；执行失败保持 `needs_review`。

页面不得出现 Veto、Quorum、投票、多轮辩论或“自动发现全部缺陷”等 v3.0.1 未提供的语义。

### 8.4 页面收束

收束句：`专家负责把问题说清楚，原 Writer 负责把结果修好，Loop 负责决定能不能关闭。`

操作：`查看支撑这一机制的平台能力`，进入 Platform Capabilities。

## 9. Platform Capabilities 页面

### 9.1 页面主张

标题：`把零散 Skills，变成留在项目里的工程系统`。

解释：AI-SDLC 不与 Coding Agent 争夺生成能力。它把团队需要长期保留的规则、状态、前端约束、验证证据和恢复路径放到项目侧。

### 9.2 能力导航

页面使用一个左侧或顶部能力选择器，右侧只展示当前能力的“现实问题、AI-SDLC 机制、可检查结果”。四个 Tab 与前台正文的四组能力一一对应，首屏默认打开“跨 AI 工具治理”。代码精简、本地优先和安全边界作为“工程控制边界”的可见子项；组件规范与浏览器验收作为“前端工程与验收”的可见子项，不再拆成与正文冲突的独立主 Tab。

| Tab | 用户问题 | 重点机制与事实边界 |
|---|---|---|
| 跨 AI 工具治理 | 换 Agent 后是否要重建项目规则 | Codex、Claude Code、Cursor、VS Code/Copilot 专用 Adapter；项目工件留在仓库，不冒充实时多 Agent 编排 |
| 断点续作 | 长任务中断后从哪里继续 | checkpoint、status、handoff、recover、显式 reconcile；恢复项目事实，不声称恢复模型内部思维 |
| 前端工程与验收 | 组件、主题、实现规则和浏览器结果如何进入同一交付上下文 | Vue 3 公共 PrimeVue 默认路径、Vue 2 企业兼容 Provider profile、高级 Style Pack 与用户确认；Browser Gate 绑定真实 origin、交互、console/page error、截图和基础可访问性；兼容项目 E2E 工件，但不冒充完整 E2E 平台、附送私有组件包或 WCAG 认证 |
| 工程控制边界 | 哪些事情必须严格，哪些事情保留工程判断 | 规则、状态和基础扫描本地优先；秘密、高风险授权和缺失证据 fail-closed；体积、重复、复杂度与职责拆分只给非阻断建议；不宣称远程 Provider 完全离线 |

### 9.3 结果展示

每个 Tab 只允许一个主视觉：真实文件入口、状态链或证据结构的产品化示意。不要同时堆叠终端、代码编辑器、浏览器和仪表盘。

页面底部用一句比较定位收束：`Prompt 和 Skills 告诉 AI 怎么做；AI-SDLC 继续管理它做到哪一步、凭什么继续，以及何时可以结束。`

操作：`下载 AI-SDLC v3.0.1`，进入 Downloads & Docs。

## 10. Downloads & Docs 页面

### 10.1 页面主张

标题：`下载正确版本，按一份指南完成接入`。

该页面是公共资源中心，不复制用户指南的安装步骤。

### 10.2 内容结构

第一屏使用两栏：

- 左侧为 v3.0.1 版本身份、GitHub、Release 和 README。
- 右侧为中文新用户指南主入口，说明指南内包含 12 条自包含路线和问题处理。

第二层使用紧凑表格提供 Windows AMD64、macOS ARM64、Linux AMD64 的正式离线安装包链接和 SHA256 链接。站点只提供链接，不打包安装资产。

页面不提供 v2 迁移指南，不提供产品契约入口，不在页面内重复 12 条安装与初始化路线。

### 10.3 离线状态

- 本地用户指南始终可以打开。
- GitHub、Release、README 和安装包按钮明确标记“需要联网”。
- 网络不可用时不弹出报错模态框，只保留可复制的目标地址和说明。

## 11. 小屏与响应式验收

必须逐一检查：

- 1440×900：标准笔记本视口。
- 1366×768：主要小屏验收视口。
- 1280×800：较窄笔记本。
- 1024×768：导航折叠和内容重排边界。
- 390×844：保证可读和可操作，不要求复刻桌面构图。

验收要求：

- 1366×768 首屏能看见完整主标题、两项主要操作和视频橱窗主体。
- 视频不会变成横跨全页的矮条，也不会挤压主标题。
- 页面没有横向滚动。
- Tab、按钮和链接的可点击区域不小于 44×44px。
- 三栏价值区在窄屏改为带分隔线的纵向列表，不变成三张卡片。
- 详情页工作区在窄屏改为阶段选择器加单列内容，不缩小到无法阅读的流程图。

## 12. 无障碍与离线约束

- 所有正文与关键交互满足可读对比度；信息不只依赖颜色。
- 视频提供字幕轨道入口、文字说明、原生控制和全屏能力。
- Tab 使用正确语义、方向键或 Tab 键可操作，并清晰显示焦点。
- 图片有替代文本；纯装饰玻璃层不进入辅助技术阅读顺序。
- 不依赖 CDN、Google Fonts、远程脚本、后台服务或构建时网络请求。
- 所有站内资源使用相对路径；外链统一标记并在新窗口打开。
- JavaScript 失败时，五个页面和用户指南仍可通过普通链接访问，核心正文仍可阅读。

## 13. 禁止项

- 不写“赛事要求”“课题一”“课题二”或评委话术。
- 不使用“30 秒看懂”“一图看懂”等答辩模板语言。
- 不伪造提效比例、缺陷发现率、成功率、客户 Logo 或用户证言。
- 不把 Bounded Dynamic Expert Review Graph 描述成持久图数据库或自主多 Agent Runtime。
- 不把 Local PR Review 画成第五个同构 Loop。
- 不把企业 Vue 2 Provider profile 写成站点附送的私有组件安装包。
- 不把 Browser Gate 写成完整 E2E 平台或 WCAG 认证。
- 不用等高卡片网格承载所有内容，不让页面退化成连续 PPT。

## 14. 设计完成门禁

进入 HTML 实现计划前，设计包必须同时满足：

1. 首页概念图、五页结构、文字入口和事实边界一致。
2. 三条首页价值与三个详情页一一对应。
3. 每个页面只有一个主任务，局部 Tab 用于探索同一主题。
4. 小屏规则、离线规则、视频占位与全屏要求已经写清。
5. 产品实践专家、AI Coding 行业专家、首次接触产品的技术评委分别完成独立评审。
6. 所有阻断已集中修正，并由三方对同一最终文件复核通过。
