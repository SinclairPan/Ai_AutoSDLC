# AI-SDLC v3.0.1 产品站数据融合设计规格

## 目标

把当前离线产品站升级为以 `v3.0.1` 比赛最终版为唯一产品事实的完整叙事：评委先看到结果证据，再理解五类 Loop、动态专家和平台治理，最后进入下载与 12 条新用户路线。

## 版本事实

- 发布标签：`v3.0.1`
- 解引用提交：`9a59a3edd483b0e6526b67b03fbfcac3ba48d2e4`
- 源码树：`fd5c2dac0a216f0eb17855d03cc7900d872d3c61`
- 产品定位：本地优先、可恢复、可验证的 AI 原生软件研发框架。
- 核心能力：Requirement、Design Contract、Implementation、Frontend Evidence、Local PR Review 五类 Loop。
- 专家边界：每个实质结果最多两名临时只读专家；原 Writer 保留修改权；最多一次修复复审；失败保持 `needs_review`。
- `v3.0.1` 与 `v3.0.0` 运行时能力一致，新增并修正 12 条安装、初始化与恢复路线。

## 数据合同

三套数据继续使用 `gpt-5.6-sol / high`、50 个优势导向工程场景和 evidence-anchored synthetic 口径。重新冻结 `v3.0.1` 能力证据后重新生成；只有能力映射复核不改变输入假设时才保留原数值。

每个数据模块提供三级披露：

1. 数字旁：`证据锚定合成评估｜50 个优势导向工程场景｜非生产统计`。
2. 展开层：模型、effort、对照组、选择偏差和无统计显著性。
3. 证据层：JSON、指标定义、场景/能力 digest、生成器和 source commit。

禁止把结果称为客户实测、生产统计、统计显著或普遍因果提升。

## 信息架构

### 首页

顺序为：版本身份与价值主张、三条证据入口、产品实录、五类 Loop 地图、动态专家、三模式能力、Local-first/恢复/跨平台、下载 CTA。三条证据入口分别使用验收 `52→90`、追踪 `55→92`、严重缺陷 `9→2`。

### Loop Engineering

用四行哑铃图展示需求理解、需求设计、开发追踪、代码质量。五类 Loop 按任务事实路由，不描述为所有任务都必须执行的固定五步。

### Dynamic Expert Review

以残余严重缺陷 `9→2` 为主证据、问题发现率 `54→89` 为副证据；五类 Loop 质量差异用成对横条呈现；机制顺序为风险路由、冻结快照、只读专家、Findings、原 Writer 修复、一次复审、Close/Stop。

### Platform Capabilities

首屏只显示验收、人工接管、成本三项。14 指标按质量、效率成本、连续性、审计治理四组展开，三种方式统一使用水平标尺，不使用雷达图。

### Downloads & Docs

只承担转化与信任：`v3.0.1` 身份、三平台正式离线资产、SHA 校验、Linux 边界、12 条新用户路线、v3 迁移和普通用户下一步；不放营销数据。

## 视觉与交互

继承选定稿的白色/冰蓝基底、深海军蓝、克制钴蓝、暖金、玻璃层叠和编辑式中文排版。视频在桌面首屏最多占 35%，不承担主证据；移动端置于证据和 CTA 后。数据图在移动端改为纵向指标行和原生 `<details>`，不依赖横向滚动、hover 或轮播。
