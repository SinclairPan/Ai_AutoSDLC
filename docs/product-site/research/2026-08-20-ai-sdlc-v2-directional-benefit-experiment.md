# AI-SDLC 2.0 方向性效益实验设计

## 这项实验回答什么

这不是为了制造一个“AI-SDLC 一定获胜”的数字，而是用最小仍可解释的实验回答四个不同问题：

| 问题 | 配对 | 能解释的边界 |
|---|---|---|
| 纯模型与通用开发 Skill 有何差异 | P → S | 方法型 Skill 的方向性增益 |
| 通用开发 Skill 与完整 AI-SDLC 有何差异 | S → A11 | 产品级工程系统相对单一 Skill 的方向性增益 |
| Loop 本身带来什么 | A00 → A10 | 保持 AI-SDLC 其余条件后，Loop 的方向性影响 |
| 动态专家对抗带来什么 | A10 → A11 | 保持 Loop 后，专家质疑与对抗的方向性影响 |

因此五臂不是为了扩大样本：P、S、A11 是面向产品叙事的三条主路径；A00、A10 只作为研究控制。若删掉任一控制臂，就不能分别回答 Loop 和动态专家是否真的贡献了结果。

## 为什么只保留三个任务

三个固定公开任务分别覆盖：

1. 需求与设计契约歧义：检验目标、边界和验收条件能否在实现前被澄清。
2. 前端恢复性交付：检验真实组件工程、失败恢复和浏览器验收能否闭环。
3. 多租户安全审查：检验严重缺陷能否被发现、修复并避免逃逸。

它们覆盖需求、开发、测试和安全，但每臂仅有三个观察、每任务只有一次运行。网站和报告必须同时显示：`directional engineering observation`、`n=3 per arm`、`single run per task`、`not statistically significant`、`not production SLA`、`no generalization`。这些数据只能支持方向性工程观察，不能外推成普遍生产效率或 SLA。

## 冻结矩阵与成本上限

- Writer：5 arms × 3 tasks × 1 run = 15 个会话。
- A11 Primary：每个任务 1 个，共 3 个只读会话。
- 安全 Cross-risk：仅安全任务 1 个只读会话。
- 总硬上限：19 个 Provider 会话。
- 技术重试：0；Expert 复审：0；额外或预留会话：0。
- A11 修复只能恢复原 Writer 的同一存活会话，不新增 Provider 会话；若执行环境不能保证同一会话，则不执行修复，并如实保留 Finding。

Token 与货币成本只有 Provider 返回权威 usage 时才记录；缺失时为 `null`。正式运行前不使用猜测价格推算成本，也不通过隐藏重试美化完成率。

## 公平性约束

- 所有臂固定使用 `gpt-5.6-sol`、`high`；Writer 输出上限 1800，Expert 输出上限 900。
- 同一任务的五个臂使用同一公开初态、同一公共 Prompt，仅方法指令链不同。
- 每个单元使用新的 0700 私有单根 Git 工作区；Provider CWD 固定为 `benchmark-task`。
- HOME、CODEX_HOME、Git 全局配置、插件、应用、MCP、全局规则和工具面在启动前冻结并跨臂一致。
- 盲评器只收到 opaque run ID 与 candidate snapshot，看不到臂名。
- 主质量只依据外部交付结果，不因存在 Loop 文件、receipt 或 AI-SDLC 目录加分；过程可审计性单独呈现。

## 指标与失败语义

每个单元只接受闭合 receipt：

- `external_verified_delivery`：外部验收是否通过。
- `weighted_acceptance_coverage`：加权验收覆盖率，范围 0–1。
- `severe_defect_escape_count`：严重缺陷逃逸数。
- `wall_time_seconds`：单调时钟耗时。
- `provider_sessions`：实际会话数。
- `input_tokens`、`output_tokens`、`total_tokens`、`currency_cost`：仅权威值，可为 `null`。

模型超时、非零退出或输出不合法，是该单元的终态失败，矩阵继续；Provider 5xx、网络、限流、主机、隔离或账本异常会中止整个矩阵并标记 `incomplete`。预算在 15 个单元完成前耗尽也只记矩阵不完整，不算某一臂失败。没有选择性重试。

## 页面如何展示才有说服力

首页只展示 P、S、A11 三条产品路径，回答“从纯模型、通用 Skill 到完整 AI-SDLC，交付结果如何变化”。证据页再展开 A00、A10 两个研究控制，解释 Loop 与动态专家各自贡献。

每个对比必须同时展示：

- 三个任务的原始配对值，而不是只有平均数；
- 失败单元和缺失数据，而不是只展示成功样本；
- 交付质量、耗时、会话数、Token 与成本的质量—成本前沿；
- A11 的 Primary / Cross-risk 拓扑和同一 Writer 责任边界；
- 全部六条统计与泛化限制。

页面不自动选出“赢家”。只有 15 个原始 receipt 全部存在时，才允许发布完整方向性观察。

## GO / NO-GO 与停止条件

离线预演 GO 条件：15 个真实工作区全部可准备、19 个会话按冻结顺序可模拟、第 20 次预约在启动前被拒绝、隔离攻击全部被系统策略阻断、Provider 调用为 0。

正式运行仍为 NO-GO，直到用户一次性确认模型、推理强度、19 会话硬上限、零技术重试和成本未知边界。任一基础设施异常、会话上限将被突破、隔离或账本失去可信性时立即中止；不追加样本，不改顺序，不临时放宽失败标准。
