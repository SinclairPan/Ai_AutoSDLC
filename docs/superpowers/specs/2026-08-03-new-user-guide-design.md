# AI-SDLC 全新用户中文指引设计

## 1. 目标

将 `USER_GUIDE.zh-CN.md` 重写为面向第一次接触 AI-SDLC 的普通用户操作手册。用户无需理解 Python 虚拟环境、AI-SDLC 内部状态或治理实现，只需根据自己的操作系统和项目类型逐步复制命令，即可完成安装、验证、项目初始化，并知道下一步应在 AI 对话中输入什么。

## 2. 固定基线

- 修改仓库：`https://github.com/SinclairPan/Ai_AutoSDLC`。
- 正式版本：`v1.0.1`，CLI 版本输出为 `1.0.1`。
- Windows 资产：`ai-sdlc-offline-1.0.1-windows-amd64.zip` 及同名 `.sha256`。
- macOS 资产：`ai-sdlc-offline-1.0.1-macos-arm64.tar.gz` 及同名 `.sha256`。
- Linux 资产：`ai-sdlc-offline-1.0.1-linux-amd64.tar.gz` 及同名 `.sha256`。
- AI 入口不设置唯一默认示例。手册必须按 CLI 真实顺序列出 `Claude Code`、`Codex`、`Cursor`、`VS Code`、`其他-通用`，并要求用户选择当前实际用于聊天开发的入口。
- Windows 推荐 Shell 为 PowerShell，macOS 推荐 zsh，Linux 推荐 bash；用户已经明确使用其他 Shell 时选择实际 Shell。
- 普通用户通过正式 Release 安装包安装，不要求手工创建 venv、拼装 pip 依赖或从源码运行。

## 3. 用户范围

文档只覆盖两类用户：

1. 全新用户 + 全新空项目。
2. 全新用户 + 已有项目。

不覆盖老版本升级、开发版安装、源码开发、打包发布、企业 AgentOps、内部 Lean Code 机制、本地 PR Review 或框架维护命令。

## 4. 内容结构

### 4.1 开始前

- 解释命令必须在终端执行，自然语言需求必须在用户选择的 AI 工具对话入口输入。
- 让用户先选择 Windows、macOS 或 Linux 对应命令块。
- 说明安装包目录不是业务项目目录。
- 说明解压后的安装目录属于长期运行环境；完成安装后不得移动或删除，否则包内直接命令入口会失效。
- 说明路径中的示例项目名可以替换，命令名、版本号和资产名不得自行修改。

### 4.2 第一章：全新用户 + 全新空项目

每个平台提供一条从零开始的完整路径：

1. 创建业务项目目录。
2. 回到父目录，从 `v1.0.1` Release 下载压缩包和 `.sha256`。
3. 验证压缩包 SHA256。
4. 解压并执行平台安装脚本，明确同意写入 PATH。
5. 使用安装包内的直接命令入口验证 `--version`，避免当前终端尚未刷新 PATH 导致误判。
6. 回到业务项目根目录执行 `ai-sdlc init .`；当前终端找不到裸命令时，使用安装脚本输出的完整 Direct shim 路径。
7. 在交互界面按“实际把需求发给哪个 AI 工具”选择适配器，再选择实际使用的 Shell；不得根据操作系统、模型名称或承载终端的编辑器外壳选择适配器。
8. 根据 `当前结果 / Result` 和 `下一步 / Next` 判断初始化成功。
9. 使用刚才选择的 AI 工具打开同一个业务项目目录，将给定需求模板复制到该工具的对话入口，开始第一个开发需求。

### 4.3 第二章：全新用户 + 已有项目

每个平台提供一条完整路径：

1. 进入已有项目根目录。
2. 使用 `git status` 查看当前分支和未提交改动；不是 Git 仓库时允许继续，但必须确认目录正确。
3. 在项目父目录完成正式 Release 包下载、校验和安装，避免把安装包解压进业务源码目录。
4. 回到已有项目根目录执行 `ai-sdlc init .`，按实际开发入口完成适配器与 Shell 选择。
5. 明确 `init` 只创建或维护 AI-SDLC 项目文件，不应删除业务代码。
6. 执行 `ai-sdlc adopt .`，接入已有 JSON、Markdown、TODO、issue 导出或 Git 任务线索。
7. 根据“接入已有项目”、原任务文件不会被修改、推荐继续点和生成工件判断 `adopt` 成功。
8. 根据 `adopt` 结果分支继续：推荐继续点正确时直接使用；不正确时执行输出给出的 `--prefer` 修正命令；未发现任务资料时回到所选 AI 工具补充当前目标。
9. 使用刚才选择的 AI 工具打开同一个已有项目目录，将增量需求模板复制到该工具的对话入口。

### 4.4 适配器选择合同

两个独立场景章节都必须包含同一份简明判断表，不能要求用户跨章节查找：

- `Claude Code`：实际在 Claude Code 中提交开发需求。
- `Codex`：实际在 Codex App 或 Codex CLI 中提交开发需求。
- `Cursor`：实际在 Cursor Chat/Agent 中提交开发需求。
- `VS Code`：实际在 VS Code 的 AI/Copilot 对话入口提交开发需求。
- `其他-通用`：实际使用的 AI 工具不在以上四项中。

选择依据是“需求实际提交给哪个 AI 入口”，不是编辑器窗口、操作系统、模型名称或 Shell。例如，在 VS Code 终端运行 Claude Code 时选择 `Claude Code`；通过 Cursor Agent 开发时选择 `Cursor`。CLI 自动检测只决定预选项，用户仍需核对。Windows 使用编号选择；macOS、Linux 使用方向键和回车选择。

## 5. 命令与预期结果合同

每个操作步骤固定包含四部分：

1. `在哪里执行`：明确当前目录和终端类型。
2. `直接复制`：给出完整命令块，不让小白自行拼接参数。
3. `成功时会看到`：只引用真实 CLI 输出中的稳定锚点，例如 `1.0.1`、`Initialized AI-SDLC project`、`当前结果 / Result`、`下一步 / Next`、`接入已有项目`。
4. `如果没有看到`：给出该步骤唯一优先的恢复命令或检查方法。

动态绝对路径、下载速度和扫描统计不写成固定输出。每个平台命令块先设置一次项目路径和安装路径变量，后续整块可复制执行，不要求用户在命令中逐处替换占位符。稳定文本必须来自 v1.0.1 的真实终端重放或已通过的发布 E2E 证据；受环境影响的默认项只说明“默认标记可能不同”，不得伪造固定默认值。

## 6. 异常处理

异常处理分为两层：

- 步骤内处理：下载、校验、解压、安装、PATH、初始化和接入失败时，紧邻步骤给出恢复办法。
- 文末速查表：按用户可见错误文本索引处理命令。

必须覆盖：

- GitHub 下载失败或网络超时。
- SHA256 文件缺失、文件名不匹配或摘要不一致。
- 安装包平台或 CPU 架构不匹配。
- Windows PowerShell 执行策略阻止脚本。
- `ai-sdlc` 不在 PATH。
- `No module named ai_sdlc`。
- 解压目录已有同名文件。
- 项目目录错误或不是 Git 仓库。
- 已有项目存在未提交改动。
- `init` 选择了错误的 AI 入口或 Shell，并给出使用 `adapter select` / `adapter shell-select` 重新选择的真实命令。
- `init` 显示 open gates，但 `下一步 / Next` 要求切换到 AI 对话。
- 所选 AI 工具未按项目规则工作时的最小诊断入口。

普通成功路径不要求用户手工运行 `adapter status` 或 `run --dry-run`；这些命令只在 CLI 明确要求或异常排查时出现。

## 7. 验证策略

修改完成后执行以下验证：

1. 从 `origin/main@289e551` 的独立工作树检查只有预期文件变化。
2. 对 Markdown 中全部正式下载地址和资产名执行静态检查。
3. 使用 v1.0.1 正式 Windows Release 包重放在线下载、SHA256 校验、解压、安装、版本检查、空项目交互式 `init`、已有项目 `init` 和 `adopt`。
4. 对 macOS arm64 与 Linux amd64 使用正式发布资产重放同一用户路径；当前平台执行真实本地重放，其他平台通过干净 GitHub-hosted runner 执行，不以静态阅读替代 E2E。
5. 确认已有项目业务文件在 `init` 和 `adopt` 前后 SHA256 不变。
6. 将手册中的命令和稳定输出锚点固化为文档合同测试；运行用户指南相关单元/集成测试、公开发布身份校验、`verify constraints`、Ruff、YAML 解析和 `git diff --check`。
7. 扫描并禁止旧版本号、升级章节、源码开发、打包发布和内部治理说明残留在新指南中。

## 8. 验收标准

- 小白只读与自己场景对应的一章即可完成全部操作，不需要跨章节拼命令。
- Windows、macOS、Linux 每条命令均可直接复制；仅示例路径需要替换。
- 安装、版本验证、`init`、`adopt` 均给出与真实 v1.0.1 行为一致的成功输出锚点。
- 两个场景均明确安装目录与业务项目目录的区别。
- 两个场景均列出全部五个适配器及选择依据，且下一步指向用户实际选择的 AI 工具，不出现 Codex 专属主流程。
- 已有项目路径明确验证业务文件不被修改。
- 每个平台的最终命令块在对应干净系统中逐条执行通过，实际输出包含手册声明的稳定锚点；文档 E2E 失败即视为手册未通过验收。
- 文档不包含任何老版本升级、历史版本或内部开发发布流程。
- 异常表能根据用户看到的错误定位到具体恢复命令。
