01

跨 AI 工具治理

执行入口可以替换，项目事实不跟聊天窗口走

现实问题 换 Agent 后，项目规则是否要重新解释，既有状态与工件是否只能留在上一个聊天窗口？

Canonical adapter map

Codex AGENTS.md
Claude Code .claude/CLAUDE.md
Cursor .cursor/rules/ai-sdlc.mdc
VS Code / Copilot .github/copilot-instructions.md

Adapter 对齐各工具的 canonical 入口；统一治理概念和项目工件继续留在仓库中。

可检查结果

  • canonical adapter files每个专用入口都有明确的项目侧规则载体。
  • WorkItem / Loop state工作身份、开放状态与 Close 结果由仓库工件承载。
  • evidence artifacts验证和复核 evidence 不依赖某一个 Agent 的对话摘要。

边界 这是规则入口与项目事实治理，不是实时多 Agent 编排；不同工具不会因此共享隐式会话，也不保证拥有相同能力。

02

断点续作

从当前分支和工件重建下一步

现实问题 长任务中断、会话压缩或换人后，团队如何确认当前分支、开放门禁与下一步仍然一致？

Project fact recovery

  1. checkpoint记录阶段、分支、开放门禁与下一步。
  2. status读取当前本地事实。
  3. handoff生成跨会话、跨人员可读摘要。
  4. recover比较 checkpoint、分支和项目工件。
  5. reconcile只在明确要求且条件安全时重建状态。

可检查结果

  • checkpoint阶段、分支、门禁与下一步的项目记录。
  • human-readable handoff简洁交接摘要，重要事实仍回到工件复核。
  • status / recover output指出一致项、漂移项与可执行恢复路径。
  • explicit reconcile过期状态不会静默覆盖更新后的项目事实。

边界 恢复的是项目事实，不是模型内部思维、进程栈或事务回滚；工件较新或分支不一致时，当前 run 会先停止。

03

前端工程与验收

把方案确认、主题约束与浏览器结果连成一条证据链

现实问题 组件、主题、页面实现和浏览器验收分散时，如何证明“能编译”的页面也是当前候选上真实可用的页面？

Governed frontend path

frontend requirement solution confirmation · 人工确认 Provider / Style Pack / Theme contract
默认推荐 vue3 / public-primevue / modern-saas PrimeVue + @primeuix/themes + primeicons
企业兼容 vue2 / enterprise-vue2 Provider profile 定义映射与安装策略
兼容证据 custom / no component library 项目提供可加载入口与兼容工件
真实 browser entry Browser Gate Frontend Evidence

可检查结果

  • Vue3 / PrimeVue 主题合同definePreset(Aura) + #1770e6 + darkModeSelector=false，覆盖 primary / surface / highlight，并以 theme.ts 为唯一入口。
  • 页面目录约束新项目默认 pages/；历史项目可沿用 views/，二者不同时新建。
  • 真实浏览器工件Browser Gate 绑定 origin、交互、console / page error、截图与基础可访问性结果。
  • 项目测试策略项目自己的 E2E Suite 负责覆盖策略；Playwright 或其他 Runner 可产出兼容证据。
  • 自定义或无组件库路径提供可加载 browser entry 和兼容 Browser Gate 工件后，由 Frontend Evidence 消费。

边界 enterprise-vue2 只提供企业兼容 profile，组件、网络和授权由企业环境提供；基础可访问性检查不构成 WCAG 认证，自定义前端也不承诺无需配置即可运行。

04

工程控制边界

必须证明的事情严格，需要判断的事情保留空间

现实问题 如果所有规则都同样严格，治理会僵化；如果都交给工程判断，身份、证据和安全缺口又可能被改写成完成。

Two-level control plane

Strict · fail-closed identity · evidence · provenance · security

身份漂移、缺失证据、秘密或高风险授权不满足时，停止并给出明确状态。

Advisory · non-blocking Lean Code · code simplification

体积、重复、复杂度和职责拆分给出建议，不替代行为正确性与工程判断。

规则、状态、扫描与工件采用 local-first 边界；外部 Provider 的数据处理仍由所选服务决定。

可检查结果

  • identity bindinginput_digest 与当前候选绑定，漂移时拒绝复用旧结论。
  • verification evidence测试、构建、浏览器或复核证据缺失时保持未完成。
  • explicit stop states缺少决定进入 needs_user，修复或复核缺口分别进入对应状态。
  • non-blocking advice精简建议可以解释和取舍，不改变 Loop 状态或 Close 权。

边界 不使用硬性行数阈值阻止 Close，也不把本地优先治理外推为远程 AI Provider 的离线保证；AI-SDLC 不负责自动合并或自动发布。

Prompt 和 Skills 告诉 AI 怎么做；AI-SDLC 继续管理它做到哪一步、凭什么继续，以及何时可以结束。
