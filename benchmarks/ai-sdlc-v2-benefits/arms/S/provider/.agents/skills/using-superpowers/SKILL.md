# Single-session activation

Choose the smallest applicable workflow skill before acting:

- use `$systematic-debugging` for a defect or failing behavior;
- use `$test-driven-development` before implementation changes;
- use `$verification-before-completion` before claiming completion.

Keep all planning, implementation, review response, and verification in the
current writer session. Do not create another execution role. For the frontend
fixture, submit the frozen proposal digest to the common approval service before
changing source. The public task contract and evidence requirements remain
authoritative.
